# 台股主動式 ETF 持股追蹤 Dashboard — 設計文件

日期：2026-07-04
狀態：已與使用者逐節確認

## 1. 目標

追蹤台股**全部已掛牌主動式股票型 ETF**（代號結尾 `A`；檔數以 `etf` 表為準，隨新 ETF 掛牌自然增加，文件與程式碼皆不寫死檔數），每日更新：

- 各 ETF 增持 / 減持 / 新進 / 出清了哪些股票
- 各 ETF 當前完整持股比例
- 各 ETF 績效（月/季/年報酬）與兩種勝率（擇時、選股）
- 跨 ETF 彙總視角（個股反查、集體動向、人氣持股）

產出為公開網頁 Dashboard，總營運成本 $0/月。

**海外持股範圍限定（v1）**：部分 A 結尾 ETF 持有海外股票（如 00402A、00989A、00997A 等美股型）。其持股快照與異動照常追蹤，ETF 層級指標（報酬、擇時勝率）照常計算；個股反查頁提供 holdings-only 視角（持有 ETF、合計權重走勢、事件、既有 `holding_days`），但不整合海外行情或計算個股報酬／選股勝率，名稱與產業缺漏時分別 fallback 為原代號與「未分類」。`etf` 表以 `universe`（tw/global）欄位區分，代號有效性驗證僅適用台股持倉。

## 2. 資料來源查證結論

| 來源 | 查證結果 |
|---|---|
| FinMind | 完整 dataset 清單中**無** ETF 持股明細 → 只用於股價/指數/股票基本資料 |
| TWSE OpenAPI | 全端點掃描，**無** PCF 或 ETF 持股資料 |
| 投信投顧公會 SITCA | 僅基本資料與連結，無集中持股揭露 |
| **各投信官網** | ✅ 法定每日揭露處（PCF/申購買回清單），HTML 表格或檔案，欄位含代號、名稱、權重、股數 → **持股資料唯一來源，需自建爬蟲** |
| zdsetf.com、etfinfo.tw | 既有第三方同類服務，資料源未公開 → 僅作上線後的數字對照組，不作為資料源 |

**行情資料**：FinMind 為主（可回補歷史、上市上櫃一個 dataset 全包、有含息的加權報酬指數 `TaiwanStockTotalReturnIndex`；每日僅需 2–3 次呼叫，免費層 600 次/時綽綽有餘），TWSE OpenAPI 作備援介面。

> 2026-07-07 實作查證：`TaiwanStockTotalReturnIndex` 以目前 token 可真呼叫，值欄位為 `price`；但 `TaiwanStockPrice` 與 `TaiwanStockPriceAdj` 真呼叫皆回 400，訊息為目前帳號等級不足，且 FinMind 官方文件標示還原股價 dataset 只限 backer/sponsor 會員使用。此處不可改用未還原價替代，因 spec §6 明定所有報酬用還原價；上線前需決定升級 FinMind、改接其他免費價格來源，或自建除權息還原流程。
>
> 2026-07-09 決策：不升級 FinMind。改用 **yfinance**（`.TW`/`.TWO` 代號）取得還原價序列，取代 `finmind.adj_prices()` 的資料源。FinMind 繼續負責 `TaiwanStockTotalReturnIndex`（TAIEX_TRI，已驗證可用）與 `TaiwanStockInfo`（代號/產業對照）。取捨：yfinance 為非官方套件，Yahoo 改版時可能失效，且非全部台股代號皆有資料（缺資料時該檔的個股層級指標從缺，比照海外持股的既有處理方式）；換來的是免費、零工程量的還原價來源，不必自建除權息還原邏輯。

## 3. 整體架構

```
GitHub Actions（每日排程）
  ├─ 18:30 主流程：抓全部主動 ETF 的 PCF（15 家投信 adapter）→ 抓 FinMind 行情
  │         → 驗證 → 入庫 → 計算異動/報酬/勝率
  └─ 21:30 補抓場：只重跑失敗/未更新的 ETF
        │
        ▼ 寫入（service key）
  Supabase Postgres（原始快照 + 異動事件 + 指標快取）
        │
        ▼ 唯讀查詢（anon key + RLS）
  Next.js on Vercel（Dashboard，不做計算只做呈現）
```

原則：

- **計算在寫入時做**：異動與指標每日算一次存表，前端只 SELECT
  - 進 pipeline 的三種情形：(a) 需要外部資料源抓取（行情、指數）；(b) 需要**不定長度**的歷史序列運算（報酬窗口、回合切分、勝率、超額報酬）；(c) 需要掃描**超出該頁呈現範圍**的資料（跨全部 ETF／全部日期的彙總表）
  - 例外——**呈現層聚合**：對「該頁 SELECT 範圍內的資料」（含為該功能新增、但範圍仍限於該頁實體與其相鄰交易日的查詢）做排序、分組、加總、中位數等重整，可在 `web/lib/` 純函式完成，不另建快取表。例：異動牆分組、集體動向金額、當日貢獻度（t-1 vs t）、`/signal` 的分布統計
  - 呈現層聚合的函式**必須 pure 且有單元測試**——它產出的數字在 DB 裡沒有稽核軌跡，測試是唯一的正確性紀錄
  - **資料量不是判準**，只是效能逃生門：符合呈現層聚合但實測拖慢 TTFB 時，才升級為 view 或快取表
  > 2026-07-31 新增。此前僅有「前端只 SELECT」一句，而實作上已累積三處呈現層聚合（`aggregateMoves`、`/signal` 統計、當日貢獻度），缺乏共同判準。判準取**結構性質**而非資料量：資料量會長，結構不會變。
- **原始資料 append-only**：`holdings_snapshot` 為事實來源，任何衍生表可重算
- **爬蟲失敗可見**：記錄於 `scrape_log`，Dashboard 顯示資料缺口警示

技術棧：爬蟲 Python（pandas）、資料庫 Supabase Postgres、前端 Next.js（App Router）+ Tailwind + shadcn/ui + Recharts。

## 4. 資料庫模型

| 表 | 用途 | 關鍵欄位 |
|---|---|---|
| `etf` | ETF 基本檔 | etf_id (PK)、名稱、投信、上市日、PCF 網址 |
| `holdings_snapshot` | 每日持股快照（append-only 事實來源） | PK=(etf_id, trade_date, stock_id)、股數、權重% |
| `holding_change` | 異動事件 | etf_id、trade_date、stock_id、類型(NEW/ADD/TRIM/EXIT)、股數變化、權重變化 |
| `stock_price` | 個股/ETF/指數日收盤（還原價） | stock_id、trade_date、收盤價、還原價 |
| `stock_info` | 代號→名稱→產業別對照 | 來自 FinMind TaiwanStockInfo |
| `etf_metrics` | 每日 ETF 指標快取 | 報酬(1/3/6月、1年、上市以來)、兩種勝率、vs 基準 |
| `open_position` | 全部未平倉 NEW 回合的當前狀態快取 | PK=(etf_id, stock_id, entry_date)、as_of_date、holding_days（進場日=0）、個股/基準/超額報酬 |
| `scrape_log` | 爬蟲執行記錄 | etf_id、trade_date、狀態、錯誤訊息 |

## 5. 爬蟲層

```
scraper/
├── adapters/          # 一家投信一個 adapter，實作 fetch(etf_id) -> [{stock_id, 股數, 權重}]
├── registry.py        # ETF ↔ adapter 對照；新 ETF 通常只加一行
└── pipeline.py        # 主流程：跑全部 → 驗證 → 入庫 → 記 log
```

- **隔離**：任一 adapter 失敗不影響其他家；失敗標記後由 21:30 場與隔日補抓（回看 3 天）
- **入庫前三道驗證**（任一不過 = 標失敗、不寫入，錯資料比缺資料危險）：
  1. 每筆權重皆為有限且非負數值，權重總和落在 70%–101%
  2. 持股筆數 vs 前日無突變（防解析到一半）
  3. 股票代號存在於 `stock_info`
- **觀察部位**：上游回報 `shares > 0` 且 `weight_pct = 0` 的股票仍是持股，必須納入 `holdings_snapshot`；不得由 adapter 丟棄，也不另設推定門檻或新增欄位。事件判定時把觀察部位視同尚未建立實質部位：無→觀察與觀察→無原則上不產生事件；觀察→實質的事件類型為 NEW，實質→觀察的事件類型為 EXIT，但兩種跨界都必須同時符合股數有變且權重差至少 0.05pp，避免上游四捨五入製造假進出；兩端皆為實質時套用既有 ADD/TRIM 規則。例外是股票已有未關閉的選股計分回合（NEW，或股數增幅 ≥10% 的 ADD）：進入觀察後若直接消失，消失日必須補記 EXIT 關閉所有回合；若先回到實質部位則沿用原回合，符合門檻的變化只記 ADD/TRIM，不得再記 NEW。每日 pipeline 與歷史回補都必須以 `build_rounds()` 的完整入口規則計算該日期以前的開放回合，再把股票集合傳入 diff。所有事件的 `shares_delta` 與 `weight_delta_pct` 仍記實際差值
- **異動判定以股數為準**：股數沒變只有權重變 = 純價格波動，不記事件；權重變化 < 0.05pp 忽略。兩個條件須同時成立才記事件——申購/贖回造成的全持股等比例股數變動，權重幾乎不動，會被權重門檻自然過濾，不會產生假異動
- **海外 IP 風險**：實作第一步跑探測腳本確認 15 家官網是否擋 GitHub Actions IP；若擋，備案 (a) 便宜代理 (b) 該幾家改由使用者 Mac 排程跑推上 Supabase
- **禮貌**：每日僅 ~27 次請求，間隔 1–2 秒，正常 User-Agent

## 6. 指標定義

所有價格用**還原價**（除權息調整），基準：ETF 層級 vs **0050（還原）**，個股層級 vs **加權報酬指數**。

**報酬**：近 1/3/6 月、1 年、上市以來（ETF 市價計）。期間不滿者顯示 `—`。旁列同期基準。

> 2026-07-23 決策：`etf_metrics.bench_0050_inception` 由 pipeline 寫入，起點對齊每檔 ETF 在 `as_of` 日以前的第一個有效還原價日，再取 0050 同日起第一個可用交易日計算；不得使用固定行情載入起點冒充同期。缺完整價窗時欄位為 `null`，前端顯示 `—`，不得自行計算。

**擇時勝率**：完整月份月報酬贏過 0050 的佔比，格式 `67%（8/12 個月）`，永遠帶樣本數。

**選股勝率**：
- 事件 = NEW，或 ADD 且股數增幅 ≥ 10%（過濾申購造成的等比例放大）；兩種入口建立的回合都必須由後續 EXIT 關閉
- **計分視窗 = 買進日 → (出清日 or 最新交易日)**：
  - 已出清（不論持有幾天）：以實際持有期間結算，不受門檻限制
  - 未出清且滿 **5 個交易日**：計未平倉浮動分，每日更新，出清時自然收斂為定案分（門檻為設定檔常數 `MIN_OPEN_SCORING_DAYS = 5`。查證結論：各 ETF 換股頻率差異極大——單日實測有 ETF 異動 122 筆、也有多檔為 0，且無公開的每檔持有天數統計——故此值定位為務實起始值，未平倉分與已實現分拆開顯示可容忍雜訊；累積三個月自有資料後以實測持有天數分布回測調整）
  - 未出清且未滿 5 個交易日：不計入勝率（防雜訊），但在「新倉追蹤」全揭露
- 部分減持（TRIM）不結束視窗，僅 EXIT 出場
- 顯示拆已實現/未平倉：`61%（已實現 14/22、未平倉 8/14）`；樣本 <10 淡化並標「樣本不足」
- 頁面註明：此為訊號品質指標，未計部位大小，不等於績效貢獻；日內沖銷不會出現在每日 PCF 快照中，無從計分

**新倉雷達未平倉快取與超額報酬**：
- 回合只由 NEW 開始、EXIT 結束；ADD／TRIM 不建立新回合，也不改變 `entry_date`。EXIT 後再次 NEW 視為新回合；資料起始日前已存在但從未出現 NEW 的存量持股排除，避免虛構進場日
- `open_position` 每日重建全部未平倉回合，不因滿 20 日而刪除；`holding_days` 為 `holdings_snapshot` 實際交易日序列落在 `(entry_date, as_of_date]` 的筆數，因此進場日為第 0 天。首頁雷達只讀 `holding_days < 20`，滿 20 日由視圖層移出
- 台股超額報酬公式為 `個股還原價報酬 − 加權報酬指數（TAIEX_TRI）同期報酬`。兩者必須使用相同價窗：起點取 `entry_date` 當日或以前最近的共同還原收盤日，終點取 `as_of_date` 當日或以前最近的共同還原收盤日；若起訖為同一天，兩邊報酬與超額報酬皆為 0%
- 個股與基準找不到完整共同價窗時，三個報酬欄皆為 `null`；海外持股因基準不具可比性也保持 `null`，但仍保留持有天數與共同建倉訊號，前端顯示「不適用」

**當日成分股貢獻度**（2026-07-31 新增；ETF 個別頁 §7③）：

- 公式 `contribution_i = w_i(t-1) × r_i(t)`，其中 `w_i(t-1)` 為**前一交易日快照權重**、`r_i(t) = adj_close(t) / adj_close(t-1) − 1`
- **必須用期初（t-1）權重**：`w_i(t)` 已內含當日漲跌，用它會系統性高估上漲股的貢獻。標準績效歸因一律用期初權重
- 歸因清單以 **t-1 快照**展開，非 t 快照。因此：當日 **EXIT** 的持股**計入**（開盤時持有）；當日 **NEW** 的持股貢獻為 **0**（開盤時未持有——這是正確值不是缺值），不列入貢獻度排行，但須以**列出代號**的方式註記未計入
- 三個對照數字：`估算 = Σ contribution`；`實際 = 該 ETF 自身 adj_close 當日報酬`；`差異 = 實際 − 估算`
- ⚠️ **「實際」是市價報酬，不是 NAV**（本專案無 NAV 資料源），兩者相差折溢價變動。`差異` 含現金部位、折溢價變動、盤中交易、申贖與未揭露持股，**不得標示為「未歸因」，亦不得宣稱為資料品質指標**——折溢價在定義上就無法由持股資料解釋。顯示時須列明成因
- **不設異常門檻**。差額本來就存在（如 00981A 2026-07-29 快照 51 檔、權重加總約 88.7%），先觀察實際分布再議
- 僅適用 `universe = 'tw'`；global ETF 顯示「不適用（未整合海外行情）」而非隱藏（§1 海外持股範圍限定）
- 屬呈現層聚合（§3 界線），在 `web/lib/` 純函式計算，不建快取表

**操作風格指標**（獨家數據，市面無人提供；由自有累積資料計算）：
- **中位數持有天數**：已出清回合（NEW→EXIT）持有天數的中位數
- **週換手率**：每週持股組合的汰換比例（新進+出清檔數 / 平均持股檔數）
- 用途：量化「誰是快手、誰是長線」，列入排行榜可排序欄位與 ETF 個別頁

## 7. Dashboard 頁面

**① 今日總覽（首頁）**
- 日期選擇器（預設最新交易日）
- 異動牆：NEW/EXIT 置頂，其次 ADD/TRIM，每筆含 ETF、股票、股數與權重變化
- **新倉追蹤雷達**：未滿 20 日建倉部位 + 買進至今超額報酬（每日更新），`abs(超額報酬) >= 10%` 標色（紅漲綠跌）、標持有天數、標「N 檔 ETF 近期同步建倉」共同訊號；部位滿 20 個交易日「畢業」移出雷達並獲得「長抱」徽章
  > 2026-07-31 規則修正：呈現由 `ETF × 股票` 平表改為**以股票為主體、跨 ETF 的建倉脈絡敘事**（一檔股票一組，組內列各 ETF 的建倉日與後續 ADD／TRIM 時序），並加四象限篩選頁籤（多/單 ETF × 有/無後續追買）與金額估算（用**事件當日**收盤價）。回合定義、20 交易日邊界、`open_position` 語意與超額報酬計算**皆不變**；超額報酬只留在每檔 ETF 那一條，**組標題不得放彙總報酬**（跨 entry_date 平均為量綱錯誤）。完整設計見 `2026-07-31-radar-build-narrative-design.md`
- **集體動向**：期間切換（當日/本週/上週/本月/上月，預設當日），被最多檔 ETF 加碼/減碼 Top 10；排序先 ETF 檔數、後**合計金額**（Σ 股數變化 × 當日收盤價；缺價顯示 `—`、排序時視為 0）
  > 2026-07-25 規則修正：原為「後合計權重增量」。跨 ETF 相加權重百分比在量綱上不成立——各 ETF 規模不同，百分比基數不一致（2,742 億基金的 1% ≠ 267 億基金的 1%）。跨股票排名唯一可比的共同單位是金額。異動牆依股票分組時組內為同一檔股票，改以股數（台股計張）彙總。完整設計見 `2026-07-25-change-wall-grouping-design.md`

**② ETF 排行榜**：全部主動 ETF 總表（規模、各期報酬、兩勝率含樣本數、vs 0050 與大盤、中位數持有天數、週換手率），可排序，贏基準標色。

**③ ETF 個別頁**：績效卡（含操作風格指標）、**當日成分股貢獻度**（§6；推漲/下跌 Top 3、貢獻度排行前 10、估算／實際／差異三數字，僅 `universe = 'tw'`，global ETF 顯示「不適用」）、當前持股表（附 vs 前日 / vs 20 日前權重變化、**持有天數欄**——自最近一次 NEW 起算，滿 20 個交易日標「長抱」徽章；`weight_pct = 0` 的列保留並標示「觀察部位」）、產業圓餅圖（依 `stock_info` 產業別）、異動時間軸、單一持股權重歷史折線。

**④ 個股反查頁**：以全站最新交易日呈現誰持有/誰加誰減，另顯示全體主動式 ETF 對該股合計權重走勢與最近事件；當日已 EXIT 且無持股時顯示 0 檔，不以最後正值聚合日冒充現況。海外股票提供相同 holdings-only 內容與既有持有天數，但不提供個股報酬或選股勝率。

**⑤ 交集表 / ⑥ 產業權重輪動**：橫向聚合視角（每股被幾檔 ETF 實質持有、全體產業資金流向），含兩張每日衍生表 `cross_holdings_daily`、`industry_weight_daily`。兩張衍生表的持有檔數與股數只計 `weight_pct > 0` 的實質部位；交集表明細仍讀完整快照，另以「另有 N 檔 ETF 為觀察部位」揭露 `weight_pct = 0` 的列。完整設計見 `2026-07-16-cross-holdings-rotation-design.md`。

**⑦ 訊號實證（`/signal`）**：以「進場事件」為樣本，統計建倉後 5／20／60 個交易日的前瞻超額報酬分布、共識分組（進場當日被幾檔 ETF 持有）對照、以及進場點價格百分位。事後統計，非投資建議。**進場定義採選股勝率的定義（NEW + ADD ≥ 10%），刻意與新倉雷達的窄定義不同**——目的不同，此差異須在程式碼註解寫明。**硬性前置：歷史回補與 `backfill_aggregates.py` 重跑皆完成後才可實作**（三個指標全部依賴歷史深度，且共識分組讀 `cross_holdings_daily.etf_count` 的歷史列）。完整設計見 `2026-07-30-signal-analysis-design.md`。

**全站**：資料缺口黃色警示條、手機響應式、深色模式。

- 排程（台北時間）：18:30 主流程、21:30 補抓；非交易日跳過（FinMind `TaiwanStockTradingDate` 判斷）
- 連兩場失敗 → 自動開 GitHub Issue 告警 + Dashboard 黃條
- Supabase 免費層 7 天閒置暫停：每日寫入天然保活
- **上線首日**：一次性回補各 ETF 上市日至今的股價/指數（報酬與擇時勝率即刻可算）；持股明細自上線日起累積
  > 2026-07-26 修訂：原文稱「歷史 PCF 無法回補」，經實測推翻——**部分投信的 PCF API 支援指定歷史日期查詢**。該部分 ETF（目前 12 檔）從上市日起逐交易日嘗試回補，但三道驗證不放寬；未通過的日期不寫入，因此頁面揭露的是「最早通過驗證的可用歷史日」，不保證等於上市日。上游無日期參數者仍僅有上線後資料；此不對稱由 `dashboard_etf_history_range` view 揭露並於前端標示。完整設計見 `2026-07-25-historical-backfill-design.md`
  >
  > 2026-07-31 補充：**「上游接受日期參數」不等於「請求日就是資料日」**。六支 adapter 實測結果為國泰、中信的請求日等於資料日；統一、第一金、安聯回請求日的**前一交易日**；元大回**次一交易日**。故回補一律以**交易日**（不是日曆日）位移換算請求日，並在寫入前核對上游自報的資料日等於**逐 ETF 算出的期望資料日**（多數檔等於 `trade_date`，但統一的全球型 00988A 的每日路徑本來就存前一交易日的資料，期望值為 `T-1`），不符即不寫入。三道驗證看不出日期錯位（權重、筆數、代號都正常），而 `holding_change` 由快照歷史重建，錯位會讓整段歷史的異動事件失真

## 9. 錯誤處理總表

| 情境 | 行為 |
|---|---|
| 單一投信爬取失敗 | 隔離、記 log、21:30 與隔日補抓、Dashboard 黃條 |
| 驗證不過（權重和/筆數/代號） | 視同失敗，不寫入髒資料 |
| FinMind 掛掉 | 切 TWSE 備援介面；當日指標延後一日補算 |
| Actions 整日未跑 | 隔日回看 3 天自動補；PCF 超過揭露窗口即永久缺口，頁面如實標示 |
| 新 ETF 上市 | registry 加一行（同投信）或新增 adapter（新投信） |

## 10. 明確不做（YAGNI）

- 不做使用者帳號/登入（全公開唯讀）
- 不做盤中即時更新（PCF 本來就一天一次）
- 不做自動交易或投資建議（頁面附免責聲明）
- 不爬 zdsetf.com（僅人工對照驗數）
- 不做 D 結尾債券型 ETF（範圍外，架構上 registry 可日後擴充）
